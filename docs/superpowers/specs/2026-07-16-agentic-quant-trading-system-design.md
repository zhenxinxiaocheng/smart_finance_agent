# Agent 协同量化交易系统总体设计

## 1. 文档状态

- 日期：2026-07-16
- 状态：总体设计已在对话中确认，待用户复核本文档
- 适用项目：`smart_finance_agent`
- 当前阶段：只完成设计，不修改业务代码

## 2. 业务目标

项目的最终目标不是复制一款普通股票 App，而是建设一套面向个人投资者的量化交易系统，并让现有 Agent 成为量化系统的自然语言控制层、研究编排层、持续监控层和解释层。

终局产品应具备：

- 可靠、可追溯、可重放的市场与财务数据。
- 可复用、可验证、可版本化的量化因子。
- 可新增、替换、比较、暂停、淘汰和回滚的策略体系。
- 符合 A 股交易机制的回测、模拟交易和后续实盘执行。
- 独立于策略的组合管理与风险控制。
- 能够调用量化能力但不能绕过量化和风控边界的 Agent。

当前股票、自选、持仓、行情、K 线、财务分析和投资计划功能是终局系统的产品与业务底座，不作为一次性页面功能建设。

## 3. 已确认的一期边界

- 市场范围：A 股。
- 用户范围：个人用户的持仓与自选股。
- 研究频率：日线为主。
- 决策周期：保留短期、中期和长期三个用户可编辑标签，实际周期由用户按交易习惯配置，系统不使用统一固定天数定义三个标签。
- 交易方向：一期只做多，不融资、不加杠杆、不做空。
- 执行范围：一期不连接券商、不自动下单。
- 分析定位：研究型决策支持，不承诺收益。
- 技术路线：保留 Vue、Spring Boot、Python sidecar 的现有结构，增量演进为量化内核与 Agent 控制层。
- 机器学习：在数据、因子、回测和风险治理成熟前不优先引入。

## 4. 对“系统是否优秀”的定义

赚钱是系统的终极业务目标，但绝对利润不能单独证明系统优秀，因为利润同时受本金、时间、杠杆、市场暴露和尾部风险影响。

系统的正式目标函数是：

```text
在明确的风险与交易约束内，最大化长期、扣除全部成本后的复合收益。
```

系统使用三套成绩单：

### 4.1 盈利成绩单

- 模拟盘和实盘扣除全部费用后的净利润。
- 年化复合收益率。
- 相对策略版本预先绑定基准的超额收益；大盘股票默认沪深 300，中小盘默认中证 500 或中证 1000，自定义股票池使用预先冻结的可复现基准组合。
- 不同月份、季度和市场环境下的收益稳定性。

### 4.2 生存成绩单

- 最大回撤与恢复时间。
- 年化波动率与尾部损失。
- 单股、行业、风格和策略集中度。
- 连续亏损、策略熔断和模型失效情况。

### 4.3 可信成绩单

- 样本外和 Walk-forward 表现。
- 参数扰动、成交延迟和成本翻倍后的稳定性。
- DSR、PBO 和多重检验风险。
- 回测、模拟盘和实盘之间的偏差。
- 收益是否由少数股票、交易或单一行情阶段贡献。

只有盈利、生存和可信度同时合格，利润才被视为策略优势的有效证据。

## 5. 当前问题与设计纠偏

当前投资分析已经具备行情同步、技术指标、基本面、风险提示、AI 解读和历史事件统计，但存在以下结构性问题：

- `technical-v2` 仍以固定技术规则和经验阈值为主。
- 短期、中期、长期主要复用同一套评分算法，只改变观察窗口。
- 三周期结果被简单平均，周期冲突被削弱。
- 当前“回测”是均线事件统计，不是包含账户、订单、成交和成本的策略回测。
- 个性化数量建议主要由技术评分线性映射投资现金，风险层没有最终否决权。
- 数据降级路径可能混用不同复权口径，数据标准尚不足以支撑研究级回测。
- 财务数据尚未形成严格的 point-in-time 研究快照。
- 分析快照缺少完整的数据集、因子、策略和实验版本链。

后续不通过继续堆叠页面判断、指标和提示文案解决这些问题，而是重建正式的量化领域边界。

## 6. 总体架构

统一处理链路为：

```text
数据快照
  -> 因子快照
  -> 策略信号
  -> 目标组合
  -> 风险决策
  -> 订单意图
  -> 模拟或真实成交
  -> 绩效归因
```

### 6.1 前端

Vue 前端负责：

- 股票研究、自选和持仓界面。
- 因子中心和策略中心。
- 回测实验室。
- 组合、风险和模拟交易界面。
- Agent 任务、待确认动作、运行轨迹和解释界面。

前端不计算核心因子、策略、仓位或风险结果。

### 6.2 Spring Boot

Spring Boot 负责：

- 用户、认证、权限和用户画像。
- 投资账户、交易流水、持仓和财富汇总。
- 因子、策略、实验和任务的业务元数据。
- 用户全局周期画像、单资产周期覆盖、配置解析、版本和能力约束元数据。
- Agent ReAct、工具网关、调度、pending action、审计和 trace。
- 量化任务编排、状态机和结果持久化。
- 模拟盘与未来实盘的订单、成交、对账和风险边界。

### 6.3 Python 量化内核

Python sidecar 逐步升级为量化研究与交易计算内核，负责：

- 数据源适配和标准化。
- 数据质量检查。
- 接收 Spring Boot 已解析的具体周期参数，不在计算代码中重新解释短期、中期和长期。
- 因子计算、标准化和中性化。
- 因子评估。
- 策略信号和目标仓位计算。
- 事件驱动回测。
- 组合构建、绩效统计和压力测试。

Python 服务不直接修改用户业务数据库，业务持久化仍由 Spring Boot 控制。

### 6.4 存储

- MySQL/SQLite：用户、账户、持仓、策略元数据、实验元数据、任务、风险和审计状态。
- Parquet：不可变原始数据、标准数据、研究数据集、因子矩阵和大规模回测结果。
- DuckDB：本地研究查询、横截面计算和回测数据分析。
- 内容哈希与清单文件：绑定数据版本、代码版本和参数版本。

## 7. 数据中心

### 7.1 数据分层

#### 原始层

- 保存第三方响应和原始字段。
- 只追加、不覆盖。
- 保存 provider、adapterVersion、fetchedAt、request 参数和内容哈希。

#### 标准层

- 统一证券代码、市场、交易日、货币、价格和成交量单位。
- 分离未复权、前复权、后复权和复权因子。
- 显式处理停牌、涨跌停、上市、退市、分红、送转和配股。
- 进行 OHLC 一致性、重复、缺口、异常值和跨源对账。

#### 研究层

- 按研究时点构建 point-in-time 数据集。
- 财务数据按实际公告时间生效，不能按报告期提前使用。
- 股票池保留历史上市、退市和可交易状态，避免幸存者偏差。
- 每个数据集生成不可变 datasetVersion。

### 7.2 数据质量门禁

发生以下情况时禁止生成新研究结论或交易：

- 关键行情过期。
- 复权状态不明或冲突。
- 财务公告时间缺失。
- 持仓与行情证券不匹配。
- 价格、成交量或交易日异常无法解释。
- 数据源降级后字段口径不兼容。

旧缓存可以用于只读展示，但必须显示数据时间和降级状态。

## 8. 因子中心

### 8.1 因子与普通指标的区别

MACD、RSI、PE、ROE 等首先是指标或原始特征。只有具备明确逻辑、严格时点、稳定计算、样本外验证和成本后价值，才能晋级为生产因子。

### 8.2 核心对象

- `FactorDefinition`：名称、分类、方向、经济逻辑和适用范围。
- `FactorVersion`：公式、参数、输入字段、代码哈希、生效时间和支持的预测周期范围。
- `FactorObservation`：证券、日期、原始值、标准值和数据版本。
- `FactorEvaluation`：IC、Rank IC、ICIR、分层收益、成本、容量和稳定性。

### 8.3 因子生命周期

```text
DRAFT -> RESEARCH -> VALIDATED -> PRODUCTION
                           -> DEGRADED -> PAUSED -> RETIRED
```

### 8.4 第一批因子族

- 价值。
- 质量。
- 盈利能力。
- 成长。
- 动量与反转。
- 低波动。
- 流动性与容量。
- 行业相对强弱。
- 财务风险。
- 拥挤度。

### 8.5 因子评估

至少包括：

- 数据覆盖率和缺失率。
- IC、Rank IC 和滚动稳定性。
- 在不同预测周期上的有效性、衰减速度和适用边界。
- 分位数组合收益及单调性。
- 牛市、熊市和震荡市表现。
- 行业、市值和风格暴露。
- 换手、交易成本和容量。
- 与其他因子的相关性和冗余度。
- 参数、标准化和中性化敏感性。
- 样本外衰减与生产监控。

## 9. 用户可配置的多周期研究模型

短期、中期和长期是用户表达交易习惯的三个可编辑语义标签，不是市场统一标准。量化内核不得根据标签名称写死天数、指标、因子或策略，所有计算以当次生效的具体周期参数为准。

### 9.1 周期配置对象

每个周期至少保存：

- `horizonCode`：稳定标识，默认提供 `SHORT`、`MEDIUM`、`LONG`。
- `displayName`：用户可见名称。
- `sortOrder`：用户界面的展示顺序，不参与因子或策略选择。
- `minHoldingDays` 和 `maxHoldingDays`：用户定义的预期持有区间，单位为交易日。
- `isPrimary`：是否为用户当前主要决策周期。
- `scope`：用户全局配置或单资产覆盖。
- `version`、`effectiveFrom` 和修改来源：用于复现、审计和回滚。

`SHORT`、`MEDIUM`、`LONG` 只作为稳定键和默认显示名称存在。即使某位用户把 100 个交易日定义为“短期”，量化内核也必须按 100 个交易日附近的预测目标选择因子和策略，不能套用预设的短线模型。

### 9.2 配置优先级

周期配置按以下优先级解析：

```text
单资产覆盖 > 用户全局周期画像 > 平台示例默认值
```

- 平台默认值只用于首次使用时的引导，必须来自可版本化配置，不得散落为前端、Java、Python 和回测代码中的常量。
- 用户可以一次设置自己的全局交易周期习惯。
- 用户可以为某只股票或其他资产设置覆盖值；未覆盖的周期继续继承用户全局配置。
- Agent 可以解释或起草修改，但未经用户确认不得改变周期配置。
- 每次分析、回测、模拟和未来实盘必须记录最终解析出的具体天数与配置版本，不能只记录“短期”或“长期”标签。

### 9.3 周期参数边界

系统必须区分以下参数，不能用一个“周期天数”代替全部含义：

- 用户预期持有区间。
- 因子计算回看窗口。
- 策略预测周期。
- 调仓频率和最短持仓限制。
- 回测评价窗口和策略观察期。

用户直接配置预期持有区间，其余参数由兼容的因子版本和策略版本提供。产品类型、数据频率、可用历史长度、停牌和基金申赎规则可以形成客观能力限制，但限制必须由后端能力接口和版本化元数据给出，不能伪装成短期、中期、长期的固定定义。

阻断性输入校验只保证配置结构有效：周期标识唯一、天数为正整数、最小天数不大于最大天数。周期区间重叠、存在空档或名称不符合市场常见叫法时可以提示，但不得擅自修改或拒绝保存。数据历史不足、数据频率不支持或没有兼容策略时保留用户配置，并在本次计算中返回明确的不可用原因。系统不得用统一的固定天数区间否定用户自己的交易习惯。

### 9.4 因子与策略兼容

- 每个因子版本声明经过验证的预测周期范围和衰减曲线。
- 每个策略版本声明支持的持有周期、调仓频率、资产类型和数据需求。
- 系统根据用户配置的具体天数匹配兼容因子与策略，不根据周期标签硬路由。
- 同一个标签在不同用户下可以匹配不同策略；同一策略也可以通过独立版本服务不同周期。
- 没有策略通过兼容性、样本外和成本后门槛时，系统必须返回“当前周期没有可靠策略”，不能强行生成交易建议。
- 用户修改周期后，相关分析缓存失效，因子、信号、回测、风险参数和结论按新配置重新计算。

### 9.5 多周期结论

- 三个用户周期分别保留结论、证据、可信度、具体天数、配置版本和失效条件。
- 综合结论由显式的证据综合与冲突处理规则产生，不做简单平均。
- 周期冲突必须直接展示，例如“你的短期配置偏强、中期配置中性、长期配置估值偏高”。
- 用户主要周期优先决定操作语义；其他周期用于暴露冲突和风险，不能替代主要周期。
- 数据不足或没有兼容策略时允许无结论，不使用默认 50 分掩盖不确定性。

## 10. 策略中心

### 10.1 策略定义

策略由以下内容组成：

- 适用市场和股票池。
- 因子版本和组合权重。
- 支持的预测与持有周期范围。
- 过滤条件。
- 信号生成规则。
- 调仓频率。
- 组合构建方法。
- 买入、持有、减仓和退出规则。
- 风险需求和容量限制。
- 适用市场状态和失效条件。

### 10.2 策略生命周期

```text
DRAFT -> VALIDATING -> PAPER -> ACTIVE
                  -> DEGRADED -> PAUSED -> RETIRED
```

### 10.3 策略版本

- 任何因子、参数、股票池、调仓或退出规则变化都创建新的 `StrategyVersion`。
- 每个策略版本绑定支持的周期范围，并记录生成信号时使用的周期配置版本。
- 历史版本不可覆盖。
- 每个回测、模拟盘和订单都绑定具体策略版本。
- 支持新旧版本并行、灰度、替换和一键回滚。

### 10.4 策略接入渠道

- 系统内置策略。
- 受控声明式策略配置。
- 开发者策略插件。
- 导入的可信策略包。
- Agent 生成的策略草案。

一期不允许导入任意未审计 Python 代码。Agent 生成的策略只能进入草案和研究环境。

### 10.5 多策略

系统不依赖单一策略。不同逻辑和周期的策略可以并行运行，由组合层分配资金。没有策略通过条件时，现金是合法仓位。

## 11. 实验与回测中心

### 11.1 实验不可变

每次实验记录：

- hypothesisId。
- datasetVersion。
- factorVersion 列表。
- strategyVersion。
- horizonProfileVersion 和解析后的具体周期参数。
- 参数和搜索空间。
- 代码提交或内容哈希。
- 训练、验证、Walk-forward 和样本外区间。
- 尝试次数。
- 结果、错误和失败原因。

失败实验同样保留，防止只展示成功结果。

### 11.2 A 股事件驱动回测

必须模拟：

- 使用当日可获得信息生成信号。
- 次日或规则指定时点成交。
- T+1。
- 涨跌停、停牌和无流动性。
- 100 股整手。
- 佣金、印花税、过户费。
- 滑点、容量和部分成交。
- 分红、送股、配股和除权。
- 资金、持仓、订单、成交和现金流水。

### 11.3 验证流程

```text
数据门禁
  -> 训练研究
  -> Walk-forward
  -> 参数锁定
  -> 独立样本外
  -> 参数扰动
  -> 成本翻倍
  -> 延迟成交
  -> 极端行情压力测试
  -> 模拟盘
```

独立测试集一旦被用于调参，就不再是独立测试集。

### 11.4 绩效指标

- 净利润和 CAGR。
- 相对基准的超额收益。
- Sharpe、Sortino、Calmar。
- 最大回撤、恢复时间和尾部损失。
- 胜率、盈亏比、利润因子和连续亏损。
- 换手、成本、滑点和容量。
- DSR、PBO 和多重检验风险。
- 不同市场状态、行业和时间窗口稳定性。

## 12. 组合与风险中心

### 12.1 分层职责

- 策略输出信号或目标权重建议。
- 组合层合并多策略目标，处理相关性、冲突和资金分配。
- 风险层检查所有硬限制并拥有最终否决权。
- 执行层只接收风险批准后的订单意图。

### 12.2 初始安全边界

在系统尚未获得真实证据前采用保守默认值：

- 不融资、不加杠杆、不做空。
- 单股最高占组合 8%。
- 单一行业最高占组合 25%。
- 单笔交易预期损失不超过组合资产 0.5%。
- 组合回撤达到 8% 时，将组合新增风险预算降为正常值的 50%。
- 组合回撤达到 12% 时，停止所有策略开新仓，只允许风险降低型订单。
- 组合回撤达到 15% 时，冻结全部策略的新订单并进入人工复核；单个策略的降级和停用另按其独立回撤分布与生产阈值执行。
- 数据、模型、订单或对账异常时禁止生成新交易。

这些边界只能基于样本外、模拟盘和真实运行证据调整，不能为了优化历史曲线而放宽。

### 12.3 策略失效处理

系统区分：

- 正常统计回撤。
- 市场状态不适配。
- 数据问题。
- 执行问题。
- 策略优势衰减。

处理流程：

```text
监控异常
  -> 降低或冻结风险
  -> 诊断原因
  -> 保持、切换市场状态、修复、重新验证或淘汰
```

禁止亏损后直接修改原策略参数。新参数必须创建新版本并重新验证。

## 13. 模拟与交易执行

### 13.1 模拟盘

- 与回测共用信号、组合、风险、费用和订单模型。
- 使用当日真实可用行情推进。
- 记录拒单、部分成交、滑点和对账偏差。
- 至少连续运行 6 个月且完成不少于 100 笔相互独立的平仓交易后，才允许评估小资金实盘；任一条件未满足都不得晋级。

### 13.2 后续实盘

实盘阶段才增加：

- 券商适配器。
- 幂等订单和订单状态机。
- 重复下单保护。
- 资金与持仓对账。
- 紧急停止和恢复流程。
- 日终核对与审计。
- 小资金灰度和逐级扩容。

## 14. Agent 协同设计

### 14.1 核心边界

量化系统是计算和风险的事实源，Agent 是控制层。LLM 只能表达工具调用意图，由应用执行受控工具。

Agent 不能：

- 自行计算或篡改收益、因子、仓位和风险结果。
- 直接执行任意代码。
- 绕过策略、组合或风险引擎。
- 修改历史实验。
- 自动启用自己生成的因子或策略。
- 未经确认建立持续行为或真实交易。

### 14.2 工具分级

#### 只读工具

- 查询行情、因子、策略、实验、组合和风险。
- 解释某次信号、回测和绩效归因。

#### 研究工具

- 创建研究任务。
- 运行因子评估、回测、Walk-forward 和压力测试。
- 比较策略和版本。

#### 变更工具

- 提交因子或策略草案。
- 调整模拟资金分配。
- 启用、暂停、替换或回滚策略。
- 创建模拟订单或未来实盘订单。

变更类工具继续通过 `ToolRegistry`、权限、风险分级和 pending action 执行。

### 14.3 Agent 价值

Agent 负责：

- 把自然语言目标转成结构化研究任务。
- 自动编排数据检查、研究、回测和压力测试。
- 解释策略盈利来源、风险和失效条件。
- 每日监控策略、组合、数据和模型漂移。
- 发现策略衰减并建议降级、替换或淘汰。
- 通过周期任务持续运行监控工作流。
- 将所有工具调用、结果和决策绑定 traceId。

## 15. 产品界面规划

最终产品逐步形成：

- 股票研究页。
- 自选股与研究股票池。
- 用户全局周期画像与单资产周期覆盖设置。
- 因子中心。
- 策略中心。
- 回测实验室。
- 组合与风险中心。
- 模拟交易中心。
- 绩效归因页面。
- Agent 任务、待确认动作和监控中心。

当前阶段不优先建设社区、热点榜单、资讯门户和装饰性 AI 功能。

## 16. 错误与降级

- 数据失败：保留旧数据只读展示，禁止生成新信号。
- 因子失败：标记缺失原因，不用默认分数填充。
- 策略失败：隔离单个策略，不影响其他策略和账户账本。
- 回测失败：保存错误和中间状态，不产生可晋级结果。
- 周期配置不兼容：说明数据、因子或策略不满足的具体条件，不回退到写死的默认周期。
- 风险失败：默认拒绝新订单。
- Agent 失败：保留量化结果，Agent 解释不可用不影响量化计算。
- 模拟或实盘对账失败：冻结新订单并升级告警。

## 17. 测试与验证

### 17.1 数据

- Provider 合约测试和固定样本回放。
- 复权、公司行为、停牌、退市和交易日历测试。
- point-in-time 财务数据测试。
- 跨源一致性和质量门禁测试。

### 17.2 因子

- 公式和输入滞后测试。
- 缺失、去极值、标准化和中性化测试。
- 无未来数据测试。
- 因子评估和版本复现测试。
- 同一因子在声明周期内外的兼容性和衰减测试。

### 17.3 策略与回测

- 信号时间与成交时间测试。
- T+1、涨跌停、停牌、整手和费用测试。
- 资金、持仓、订单和成交不变量测试。
- Walk-forward、样本外锁定和实验不可变测试。
- 回测、模拟盘共用逻辑的一致性测试。
- 用户全局配置、单资产覆盖、配置继承、修改重算和版本复现测试。
- 扫描前端、Spring Boot、Python 和回测链路，确保不存在决定短中长期含义的散落硬编码。

### 17.4 风险与执行

- 单股、行业、策略、回撤和损失限制测试。
- 风险拒绝优先级测试。
- 幂等订单、重复下单和对账测试。
- 策略降级、暂停、淘汰和回滚测试。

### 17.5 Agent

- 工具可见性与执行权限分离测试。
- 研究工具不可直接改变生产状态测试。
- 变更工具 pending action 测试。
- trace、调度、失败熔断和审计测试。

## 18. 实施阶段

### 阶段一：可信股票分析底座

- 修复行情复权、数据口径和质量门禁。
- 建立 point-in-time 财务数据边界。
- 将现有三周期分析重建为用户全局可配置、单资产可覆盖、全链路可复现的多周期分析。
- 建立因子定义、版本和最小评估闭环。
- 建立策略定义、版本和状态基础。
- 将历史事件统计升级为可成交回测。
- 分离信号、组合、风险和数量建议。
- 为 Agent 提供结构化只读研究工具。

### 阶段二：量化研究平台

- 扩展市场级研究数据。
- 建立因子矩阵、因子中心和策略中心。
- 建立实验登记、Walk-forward、样本外和压力测试。
- 支持声明式多因子策略和策略比较。
- Agent 编排研究任务和持续监控。

### 阶段三：模拟交易

- 建立模拟账户、订单、成交和绩效归因。
- 多策略组合、风险预算和策略替换。
- 策略衰减监控、Champion-Challenger 和灰度切换。

### 阶段四：小资金实盘与扩容

- 券商适配、对账、紧急停止和审计。
- 小资金运行、真实偏差监控和逐级扩容。
- 实盘变更继续由 Agent 起草、风险引擎审批、用户确认。

## 19. 阶段一验收标准

- 同一数据版本、因子版本、策略版本和参数能复现相同结果。
- 每个股票分析结果能追溯数据时间、来源和规则版本。
- 三个用户周期按最终解析出的具体天数独立计算并展示冲突，不再简单平均。
- 修改用户全局周期或单资产覆盖后，分析、因子、策略、回测和风险参数使用同一周期配置版本重算。
- 前端、Spring Boot、Python 和回测模块不分别写死短期、中期、长期的天数定义。
- 数据不足或异常时不强行产生结论。
- 至少一个透明因子完成定义、计算、评估和版本闭环。
- 至少一个策略完成定义、版本、回测和状态闭环。
- 回测模拟 A 股主要交易约束和成本。
- 策略不能直接生成最终订单，风险层可以拒绝。
- Agent 只能基于结构化研究结果解释，不能覆盖计算结果。
- 不连接券商、不自动交易。
- 保持现有股票、持仓、财富和 Agent 主流程兼容。

## 20. 非目标

当前不承诺：

- 任何固定收益率或保证盈利。
- 一期直接连接券商。
- 一期实现高频或分钟级交易。
- 一期支持融资融券、期权、期货或做空。
- 一期允许任意第三方代码在本机执行。
- 一期使用复杂机器学习替代透明研究流程。
- 使用一套统一固定天数定义所有用户的短期、中期和长期。
- 一次性完成所有终局页面和模块。
