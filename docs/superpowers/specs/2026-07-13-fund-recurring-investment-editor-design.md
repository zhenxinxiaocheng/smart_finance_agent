# 基金编辑页定投计划设计

## 目标与范围

- 仅在基金资产的编辑抽屉中展示定投计划，股票不展示。
- 每个用户的同一基金资产只维护一条定投计划。
- 支持新增、查看、修改、启用/暂停和删除计划。
- 定投计划仅用于记录安排，不自动扣款、下单或修改持仓。

## 页面交互

- 在“编辑持仓”下方增加“定投计划”卡片。
- 未创建时展示金额、频率、执行日和启用状态表单，保存后创建计划。
- 已创建时使用相同表单编辑，并显示后端计算的下次执行日期。
- 频率支持“每周”和“每月”：每周执行日为周一至周日，每月执行日为 1 至 28 日。
- 删除计划前弹出确认对话框；删除基金资产时同时删除其定投计划。
- 定投表单与持仓表单分别保存，实时行情轮询不得覆盖正在编辑的表单。

## API 与数据流

- 新增 `GET /api/investment/assets/{assetId}/plan`，返回该基金资产的计划；没有计划时返回空数据。
- 新增 `PUT /api/investment/assets/{assetId}/plan`，根据资产执行新增或更新。请求只包含 `amount`、`frequency`、`executionDay` 和 `enabled`。
- 新增 `DELETE /api/investment/assets/{assetId}/plan`，删除该资产的计划。
- 后端从资产记录取得 `accountId` 和 `productId`，前端不要求用户选择账户或产品。
- 现有 `/api/investment/plans` 接口继续保留，避免影响已有调用。
- 新的资产级保存逻辑会复用同一条计划；现有通用创建接口也应拒绝同一用户、账户和产品的重复计划。

## 日期与校验

- 金额必须大于 0，并使用 `BigDecimal` 保存。
- `WEEKLY` 的执行日范围为 1 至 7，1 表示周一；`MONTHLY` 的执行日范围为 1 至 28。
- 下次执行日期由后端按服务器日期计算：若当前周期的执行日尚未过去则取本周期，否则取下一周期。
- 修改频率或执行日、重新启用计划时重新计算下次执行日期。
- 所有资产和计划操作必须同时校验 `userId`；股票资产调用定投接口应返回业务错误。

## 删除边界

- 删除定投计划只删除计划，不影响基金资产、持仓和历史流水。
- 删除基金资产时先删除其计划，再执行现有持仓冲正和资产软删除，避免孤立计划。

## 测试与验收

- 后端覆盖创建、更新、启停、删除、重复创建、日期计算、股票拒绝和跨用户访问。
- 前端覆盖仅基金展示、计划加载、频率切换、执行日范围、保存和删除确认。
- 最终运行前端测试与构建、后端投资模块测试，并在 `/stocks` 实际验证基金抽屉。

## 非目标

- 不接券商或基金平台自动扣款、申购和下单。
- 不新增定投独立页面，不支持同一基金多条计划，不生成自动交易流水。
