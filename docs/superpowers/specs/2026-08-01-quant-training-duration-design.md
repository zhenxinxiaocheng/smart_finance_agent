# 量化训练时长标识设计

## 目标

量化模型管理页在训练进行中显示“已运行”和“预计时长”，避免只有旋转图标而无法判断任务是否仍在推进。训练完成后显示实际耗时。

## 数据契约

- 分析服务在创建量化任务时返回 `estimatedDurationSeconds`。
- 估算值由同一份量化配置计算：参数搜索时间预算，加上按目标、基准及研究池记录数估算的预处理时间和收尾时间。
- 预处理单条记录成本和收尾时间放入 `quant-research-v2.json`，不在 Python、Java 或 Vue 中写死。
- 后端将估算秒数持久化到 `quant_job`，MySQL、SQLite 和 H2 测试结构同步迁移。
- 模型管理接口的 `training` 增加：
  - `startedAt`
  - `estimatedDurationSeconds`
  - `actualDurationSeconds`（仅结束后存在）

## 页面行为

- `QUEUED`：显示预计时长，不显示运行计时。
- `RUNNING/OPTIMIZING/PREPARING_DATA`：每秒在浏览器本地更新“已运行”，不增加接口请求。
- 超过估算值：显示“已超过预计时长”，任务仍继续运行。
- 已完成或失败：停止计时，显示实际耗时。
- 缺少估算值的历史任务显示“预计时长：计算中”，不伪造固定分钟数。

## 测试

- Python：覆盖数据规模估算、配置驱动和非训练任务不估算。
- Spring：覆盖创建任务时持久化估算值、轮询同步和管理接口时长字段。
- 前端：覆盖中文时长格式、运行中、超时和已完成状态。

## 边界

本次只增加时长信息，不改变训练预算、停止条件、候选选择或模型晋级规则。
