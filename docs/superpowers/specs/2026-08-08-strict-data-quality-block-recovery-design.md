# 数据质量阻断与自动恢复设计

## 目标

数据质量门禁只在证据确实不可信时进入 `BLOCK`。一旦阻断，用户接口不得返回旧技术结论、基金动作、回测或 AI 解读；系统必须在数据恢复可信后自动生成新结果。

## 状态语义

- `PASS/WARN + ALLOW`：允许生成并展示当前数据对应的分析。
- `BLOCKED + BLOCK`：数据完整性规则失败，禁止生成或展示任何分析结论。
- `UNAVAILABLE/WAITING`：供应商超时、分析服务不可用、规则服务异常等运行故障；不得伪装成数据质量 `BLOCK`，也不得展示旧结论。
- 历史快照继续保存在数据库用于审计，但不进入阻断或等待状态下的普通详情响应。

## 调用与恢复流程

1. 详情请求先读取最新质量状态。
2. `ALLOW` 时才允许按数据集版本、规则版本、周期配置、策略版本和最新行情日期判断缓存命中。
3. `BLOCK` 或 `UNAVAILABLE` 时返回空分析结构和明确原因，同时确保存在一个去重的数据恢复任务。
4. 已处于 `QUEUED/RUNNING/RETRY_WAIT` 的恢复任务不得被详情请求重置。
5. 恢复任务强制重新拉取数据并重新执行质量校验；第一次失败等待 60 秒，第二次失败等待 300 秒，第三次失败进入 `FAILED`。
6. 新质量结果为 `ALLOW` 后，立即用新数据重新计算技术分析、基金周期结果和回测，并原子更新当前规则版本的分析快照。
7. 前端轮询恢复任务；成功后重新加载详情并展示新结果，失败时仅展示失败原因和人工重试入口。

## 防止误阻断

- 不降低必填字段、日期唯一性、正值、快照完整性、净值类型一致性和正式净值等关键规则。
- 基金陈旧和日期缺口继续保持警告阈值；单个警告不得升级成 `BLOCK`。
- 网络、供应商和服务异常使用运行状态表达，不写入数据质量 `BLOCK`。
- 同一资产同一任务类型只允许一个活动恢复任务，避免重复请求供应商。

## 接口表现

阻断或等待时：

- `technicalAnalysis.status` 为 `BLOCKED` 或 `UNAVAILABLE`；
- `fundamentalAnalysis`、`backtestSummary`、`aiExplanation` 不包含旧结论；
- `sourceStatus` 提供质量状态、决定、失败规则或运行错误、恢复任务状态；
- `quoteSeries` 可继续展示已落库的原始行情，但不得附带旧分析指标和动作。

## 验收条件

- 质量 `BLOCK` 且数据库存在旧快照时，详情响应不包含旧分析内容。
- 供应商异常显示 `UNAVAILABLE/WAITING`，不显示为数据质量 `BLOCK`。
- 连续详情请求不会重置正在运行的恢复任务。
- 恢复为 `ALLOW` 后自动生成新快照，数据集和周期配置与当前请求一致。
- 基金 `WARN + ALLOW` 仍可正常分析；关键完整性规则失败仍会阻断。
- 后端单元测试、投资模块集成测试、Python 质量规则测试和前端构建全部通过。
