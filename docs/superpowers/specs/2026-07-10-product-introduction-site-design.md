# 智财 Agent 产品介绍站设计规格

## 目标

在现有 `smart_finance_agent` 仓库中新增一个独立的产品介绍站，用于毕业答辩、项目展示和潜在用户了解产品。网站完成后通过 Sites 私有发布，交付一个可访问的私有链接。

介绍站只展示产品价值、真实功能、运行机制和技术架构，不连接生产数据库，不调用现有后端接口，也不修改当前前端和后端业务流程。

## 受众与核心叙事

- 主要受众：答辩评审、项目访客、潜在用户。
- 首屏核心信息：智财 Agent 不只是聊天机器人，而是能记账、分析、记忆，并在确认后执行任务的个人财务代理。
- 主要行动按钮：跳转到 GitHub 仓库 `https://github.com/zhenxinxiaocheng/smart_finance_agent`。
- 次要行动按钮：平滑滚动到“核心能力”区域。

## 项目边界

- 新站放在仓库根目录的 `product-site/` 中，拥有独立依赖、构建和托管配置。
- 使用 Sites 的 Vinext/React 项目结构和 Cloudflare Worker 兼容构建输出。
- 复用 `frontend/public/` 下现有产品截图，但在介绍站中保存独立副本，避免构建时跨项目引用。
- 不修改 `frontend/`、`backend/`、启动器或数据库配置。
- 不增加登录、表单、持久化、上传或外部数据接口。
- 不把 `.superpowers/brainstorm/` 设计预览纳入产品站提交或部署。

## 页面结构

页面为单路由长页面，按以下顺序组织：

1. 顶部导航：品牌标识、产品、能力、架构、源码锚点。
2. 首屏：核心定位、简短说明、GitHub 主按钮和“了解核心能力”次按钮。
3. 产品价值：解释从普通财务工具到可信财务 Agent 的变化。
4. 核心能力：财务管理、ReAct 与 RAG、长期记忆、Skills、周期任务、反思、账单导入、财务画像、安全审计。
5. 任务运行流程：用户目标 → ReAct 决策 → 工具调用 → 人工确认 → 执行结果与审计记录。
6. 真实产品界面：展示新对话、统计分析和财务画像截图，并补充账单导入与周期任务说明。
7. 系统架构：Vue 3 交互层、Spring Boot 业务与 Agent 编排层、MySQL/DashScope/RAG/搜索能力层。
8. 安全与可追踪：写操作先确认、账单识别只生成候选、traceId 与运行步骤可回看、敏感信息不自动沉淀。
9. 技术栈与页尾：列出主要技术，重复 GitHub 行动入口。

## 视觉系统

### 总体方向

产品介绍页使用“工程叙事”风格：清晰的编号、网格、细分隔线和分层信息结构。进入聊天、账单和数据截图展示区域时，适当融合“温润可信”风格，通过柔和表面、圆角卡片和更舒展的留白降低技术页面的冷硬感。

### 色彩

- 页面背景：暖灰白 `#F3F0E9`，不使用纯白。
- 主要文字：深灰黑 `#292725`，不使用纯黑。
- 次要文字：暖灰 `#67625B`。
- 品牌强调色：低饱和陶土橙 `#B65D3D`。
- 边界线：暖灰线条 `#C9C2B7`。
- 柔和卡片表面：`#FAF8F3`。
- 强调色只用于主按钮、选中状态、当前流程节点、编号和关键数字，不扩散为装饰色。

### 字体与间距

- 使用系统无衬线字体栈，中文优先使用系统中文字体，避免额外字体加载依赖。
- 中文大标题字重控制在 `600–620`，正文和卡片标题使用 `400–650`，不采用全页超粗标题。
- 正文行距约 `1.75–1.85`。
- 桌面端主要区块上下间距约 `80–112px`，移动端约 `56–72px`。
- 卡片之间保持至少 `12–20px` 间距，正文段落与标题之间保持清晰呼吸空间。

### 图像与图标

- 产品截图使用仓库现有真实 PNG，不制作伪造产品界面截图。
- 页面不使用模型生成的 SVG 插画；图标仅使用项目依赖中可用的通用图标或 CSS 几何标记。
- 实现阶段生成一张与最终页面一致的社交分享图；若文字检查不通过，则不配置分享图。

## 交互与响应式

- 导航锚点和次按钮使用平滑滚动。
- GitHub 链接在新标签页打开，并提供明确的可访问名称。
- 能力卡片、流程节点和截图只使用轻量悬停/聚焦反馈，不加入复杂轮播或无意义动画。
- 首屏和主要区块允许短促的进入动画，但必须遵循 `prefers-reduced-motion`。
- 键盘用户可以访问全部链接和按钮；焦点状态使用品牌强调色并保持足够对比度。
- 桌面端采用多列网格，平板端减少列数，移动端改为单列；不出现水平滚动。

## 内容与数据流

网站内容全部为构建时静态内容：

- 产品事实来自当前 README、前端路由和实际实现。
- 产品截图来自当前仓库静态资源。
- GitHub 是唯一外部跳转。
- 页面不读取用户数据，不使用浏览器存储，不调用智能财务系统 API。

因此不存在运行期业务数据错误。构建阶段必须验证所有截图资源、锚点和链接均存在；资源缺失应导致测试或构建失败，而不是发布带空白占位的页面。

## 测试与验收

实现采用测试优先流程，至少覆盖：

- 页面渲染核心标题和九个内容区块。
- GitHub 主按钮使用正确地址和安全的新标签页属性。
- 页面内导航锚点指向真实区块 ID。
- 产品截图均具有替代文本并可由构建系统解析。
- 页面不存在纯白 `#FFFFFF` 或纯黑 `#000000` 作为设计令牌。
- 移动端布局规则不会产生横向溢出。
- `prefers-reduced-motion` 下关闭非必要动画。
- `npm run build` 成功生成 Sites 要求的 Cloudflare Worker 兼容输出。
- 发布后部署状态为成功，并通过 Sites 私有访问链接打开。

## 发布

- 在 `product-site/.openai/hosting.json` 中保存 Sites 项目标识。
- 构建通过后保存一个 Sites 版本并使用私有部署。
- 交付私有部署链接，不将网站切换为公开访问。

## 非目标

- 不把现有完整 Vue 应用迁移到 Sites。
- 不在介绍站内提供真实登录、记账或聊天功能。
- 不为产品介绍站新增数据库、认证、文件上传或后台管理。
- 不重构现有智能财务系统代码。
