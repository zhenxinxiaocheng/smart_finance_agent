# 投资详情页可理解性改造设计

## 目标

保留现有技术名称、分析规则和数据结构，通过统一问号提示、结论优先的信息层级、明确的无数据原因和零值空状态，让不熟悉投资术语的用户也能理解页面当前表达的含义。

本次只调整前端展示，不修改技术评分、支撑压力、分析周期、基本面、回测、数量计算或 AI 解读的后端规则。

## 设计原则

- 技术名称保持不变，包括技术评分、多周期分析、长期基本面与估值、数量参考、财务警告、历史回测和 AI 解读。
- 页面先回答“当前结论是什么”，再展示依据和专业细节。
- 问号用于解释术语，不能代替页面本身应该提供的结论和状态说明。
- 提示文案只解释“是什么、主要看什么、不能代表什么”，默认不展示计算公式。
- 任何 `0` 或 `-` 都必须区分真实零值、当前无信号和数据不足。
- 风险偏好、现金和财务状况仍然只产生警告或数量参考，不能改变技术分析。

## 统一问号提示组件

新增可复用的 `InfoTooltip` 组件，基于项目已有 `reka-ui` Tooltip primitives 实现，不增加依赖。

组件表现：

- 使用低对比度圆形问号图标，放在模块标题或难理解字段旁边。
- 鼠标悬浮和键盘聚焦时打开，按 Escape 关闭。
- 触发器使用真实按钮并带有明确的 `aria-label`。
- 内容宽度控制在约 280px，使用两到三句短文，避免长段落。
- Tooltip 使用 Portal，避免被 Card、图表或滚动容器裁切。
- 颜色、边框、圆角和阴影沿用现有主题变量，兼容暗色模式。

首批覆盖位置：

- 当前技术评分
- 当前分析周期
- 买入观察区、加仓观察区、持有区、减仓观察区、跌破风险位
- 多周期分析与周期分歧
- 长期基本面与估值
- 数量参考
- 财务警告
- 历史回测
- AI 解读

## 页面信息层级

### 顶部结论区域

保留 K 线和右侧结论卡的总体布局，但强化三个信息层次：

1. 结论：值得关注、中性观察或技术偏弱。
2. 原因：用一行普通语言概括当前主要依据，例如趋势、动量、回撤或数据不足。
3. 行动：显示当前可用的观察区间；没有有效区间时显示具体原因。

技术评分和分析周期保留原名称，并在旁边提供问号说明。顶部不新增“新手模式/专业模式”切换，避免用户多做一次选择。

### 数量参考

数量参考不再无条件渲染三批金额：

- `suggestedBudget > 0` 时显示建议总预算和三批参考。
- `sellQuantity > 0` 时显示减仓数量参考。
- 两者都为零时，显示单一空状态：“当前技术评分没有形成明确买入或减仓信号，建议继续观察。”
- 投资账户现金为零时，说明“当前投资账户没有可用现金，因此无法换算买入数量”。
- 股票预算不足一手时，说明“按 100 股一手取整后，当前预算不足一手”，不显示三组零值。

数量参考问号明确说明：这是基于技术评分和投资账户现金的估算，不是交易指令，也不会自动下单。

### 价位状态

所有价格区间统一使用状态文本：

- 有有效值：显示价格或区间。
- 历史行情不足：显示“历史数据不足”。
- 当前算法未形成区间：显示“当前未形成有效区间”。
- 当前价格缺失：显示“缺少最新价格”。

不再使用孤立的 `-` 表达所有不同情况。

### 专业内容收纳

K 线、多周期结论、长期基本面主要结论和财务风险继续直接展示。以下详细内容放入原生 `details/summary` 的“查看详细分析”区域：

- 基本面各维度的详细分数
- 历史回测的完整指标
- AI 解读的缓存和刷新状态说明
- 技术分析边界的详细说明

折叠只改变展示密度，不删除任何已有数据。桌面端和移动端使用同一信息顺序。

## 提示文案要求

示例：

- 技术评分：“综合均线、动量、成交量等技术指标得到的 0–100 分。分数越高代表当前技术状态越强，但不代表一定上涨。”
- 多周期分析：“分别观察短期、中期和长期走势。不同周期结论不一致时，会显示周期分歧。”
- 数量参考：“根据技术评分和投资账户可用现金估算分批数量。仅作参考，不会修改技术结论或自动交易。”
- 历史回测：“统计过去出现类似信号后的表现。历史结果只能帮助理解信号，不能保证未来收益。”
- 财务警告：“根据现金、持仓集中度和财务目标产生的提醒。警告不会改变技术评分和支撑压力。”

文案集中维护在独立配置文件中，页面只引用提示键，避免同一术语出现不同解释。

## 组件边界

- `InfoTooltip.vue`：只负责触发器、浮层、无障碍属性和主题样式。
- `investmentHelpText.js`：集中存放提示键和中文解释。
- `investmentActionState.js`：将数量结果和数据状态转换为可展示状态，不修改后端结果。
- `InvestmentAssetDetail.vue`：负责页面编排，不继续堆叠提示判断和零值判断。

## 响应式与无障碍

- 触发器最小可点击区域保持约 28px，图标视觉尺寸约 14px。
- Tooltip 靠近视口边缘时自动换边，不产生横向滚动。
- 键盘用户可以 Tab 到问号并读取提示。
- 移动端保留标题下方的关键说明和状态文本；不要求用户依赖悬浮才能理解核心结论。
- 问号按钮不得抢占标题的主要视觉层级。

## 异常与兼容

- Tooltip 渲染失败不影响模块标题和业务数据显示。
- 缺失的帮助键回退到通用说明，不抛出页面错误。
- 后端旧快照缺少某些字段时，页面显示对应的数据不足原因。
- 不改变现有 API 请求、路由、K 线交互和编辑持仓流程。

## 测试与验收

- 验证问号可通过鼠标悬浮和键盘聚焦打开，并具有 `aria-label`。
- 验证主要模块均使用集中维护的帮助文案。
- 验证数量全部为零时不再显示三批 `¥0.00`。
- 验证无现金、预算不足一手、技术无信号三种状态使用不同说明。
- 验证价位缺失时不再只显示 `-`。
- 验证专业名称全部保持不变。
- 验证财务警告不会改变技术结果的现有测试继续通过。
- 验证暗色模式、390px 手机和桌面布局。
- 运行全部前端 Node 测试和 `npm run build`。
