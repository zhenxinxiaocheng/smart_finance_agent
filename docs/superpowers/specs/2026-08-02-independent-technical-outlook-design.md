# 独立技术走势分析设计

## 目标

技术走势分析与量化交易模型完全分离。即使没有通过验证的量化模型，系统也应基于当时可见的历史量价数据，像专业交易员一样给出易懂、可追溯的走势研判。

技术分析回答“当前走势偏向什么、依据是什么、风险在哪里、什么条件会推翻判断”；量化模型才回答“某套经过验证的策略是否具有可交易价值”。技术分析不得伪装成盈利概率，也不生成金额、股数或自动订单。

## 当前问题

- 系统已经计算均线、MACD、RSI、KDJ、布林带、ATR 和成交量均线，但当前技术评分主要只使用价格动量和快慢均线。
- 页面主卡由量化模型状态主导；模型不可用时，用户首先看到“暂无有效模型”，已有技术分析被弱化。
- 技术结论只有评分和宽泛标签，缺少量价配合、波动、关键价位、主要证据和判断失效条件。
- 数量参考目前会在技术评分可用时生成，与“技术分析不生成交易数量”的边界冲突。

## 方案比较

### 方案 A：确定性多因子技术研判（采用）

将趋势、动量、量价、波动和价格结构分别评分，再根据配置权重合成方向与强度。每条结论都能追溯到具体指标和历史数据，可直接使用历史时点回放同一套规则。

优点是稳定、可解释、无需等待训练；缺点是规则需要持续校准，但不会把未经验证的预测包装成概率。

### 方案 B：让大模型直接阅读指标

语言自然，但同一数据可能得到不一致结论，容易出现臆测，也难以严格回测。只适合在方案 A 结果之上做可选解释，不作为结论来源。

### 方案 C：训练方向预测模型

可能学习复杂关系，但重新引入样本、泄漏、过拟合和验证问题，无法解决“现在就需要一个可靠技术分析”的目标。它仍属于量化模型，不属于本功能。

## 分层结构

### 1. 技术研判引擎

Python 分析服务新增独立、可测试的技术研判组件，输入为：

- 截至分析时点的复权 OHLCV 历史数据；
- 用户配置的任意分析周期；
- 可选的最新换手率、量比、振幅等市场快照；
- 数据版本、规则版本和计算时间。

引擎按周期计算五个互不混淆的维度：

- 趋势：价格与周期均线关系、均线排列、均线斜率、周期收益方向；
- 动量：MACD、RSI、KDJ 的方向、拐点与过热/超卖状态；
- 量价：成交量相对历史基线、上涨放量、下跌放量、缩量整理、突破确认；
- 波动风险：ATR、布林带宽度、近期回撤和异常振幅；
- 价格结构：支撑、压力、区间位置、突破或跌破以及关键价位触碰次数。

所有周期、阈值、权重和分段规则放在版本化 JSON 配置中。用户修改分析周期后，引擎直接使用新的周期边界，不依赖 `SHORT/MEDIUM/LONG` 或固定天数。

### 2. 结论合成

输出方向使用五级枚举：`BULLISH`、`LEAN_BULLISH`、`SIDEWAYS`、`LEAN_BEARISH`、`BEARISH`。同时输出：

- `strength`：0～100 的方向强度，不称为盈利概率；
- `confidence`：指标一致度和数据完整度形成的高、中、低置信度；
- 最多三条主要依据；
- 最多三条风险；
- 支撑、压力和判断失效价位；
- `WATCH`、`WAIT`、`AVOID`、`REDUCE_WATCH` 等观察方向，不含交易数量；
- 各维度分数、原始指标、数据及规则来源，供详情展开。

基本面和财报保持独立板块。它们可以形成“长期质量观察”，但不得修改技术走势方向。AI 只能把上述结构化结果翻译成短句，不能新增指标、价格或操作结论。

### 3. 数据不足处理

不再因某个最长指标不可计算就让整个技术分析消失：

- 核心量价数据达到配置的最低要求时，输出 `LIMITED` 结果，并降低置信度、明确缺少的维度；
- 所有配置维度均可计算时输出 `READY`；
- 只有 OHLC 数据本身不足或质量阻断时才输出 `INSUFFICIENT`；
- 历史可靠快照可展示，但必须标注数据日期和“历史快照”，不得冒充实时结果。

### 4. 历史验证

技术分析使用与当前结论完全相同的规则做逐时点回放：每个历史时点只能读取当日及以前的数据，再观察用户所选周期后的实际走势。展示：

- 相似方向出现次数；
- 上涨比例、下跌比例和中位收益；
- 最大不利波动；
- 判断被失效价位推翻的比例；
- 数据区间、规则版本和样本限制。

这些统计用于说明规则过去的表现，不称为未来盈利概率，也不决定量化模型是否晋级。

## 页面设计

- K 线右侧主卡改为“走势研判”，默认展示当前配置周期的方向、强度、置信度、三条依据、风险位和失效条件。
- 多周期卡展示每个用户配置周期的方向和主要分歧，不假设固定三个周期。
- 技术指标详情和历史验证放在可展开区域，普通用户无需阅读全部指标。
- “量化模型”成为独立次级板块；没有有效模型时只说明模型仍在研究，不遮挡技术分析。
- 删除由技术评分生成的数量参考。只有经过部署门槛的量化策略才可以进入金额和数量计算。

## 数据流与接口

`历史行情/最新市场快照 -> 数据质量检查 -> 技术研判引擎 -> 版本化分析快照 -> Spring 接口 -> 详情页`

技术分析响应增加 `outlook`：方向、强度、置信度、证据、风险、失效条件、维度分数和来源。旧的 `score/verdict/signals` 保留一个兼容周期，由新结构派生，避免前端与已保存快照同时失效。

量化预测接口、模型状态和训练任务不参与这条调用链。

## 错误与安全边界

- 缺失指标只降低相应维度的可用性，不用零值冒充真实结果。
- 换手率或量比不可用时明确标记缺失，不从成交量猜造。
- 技术分析不输出“保证上涨”“盈利概率”或自动交易承诺。
- 数据质量阻断、日期过期和历史快照必须在主结论附近显示。

## 测试与验收

- Python：覆盖五个维度、配置周期、量价背离、突破确认、数据不足降级和无未来数据泄漏。
- Spring：覆盖可选市场快照、版本追溯、历史快照标记，以及技术分析与量化状态互不影响。
- 前端：覆盖无量化模型时仍优先显示走势研判、任意周期、短摘要、展开详情和不显示数量建议。
- 验收样本至少包含上涨趋势、下跌趋势、缩量震荡、放量突破和放量下跌；逐项核对证据与原始行情一致。

## 完成标准

任一具备最低可靠历史数据的股票，即使没有可用量化模型，详情页也能在一次加载中给出有来源的技术走势方向、主要依据、风险位和历史规则表现；页面不会再以“暂无有效模型”作为主要结论。
