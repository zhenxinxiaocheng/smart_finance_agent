# 指数基金基准相对分析设计

## 目标

先为境内 `INDEX_FUND` 建立可审计的基准相对分析。短、中、长周期继续严格使用用户设置的 `targetDays` 独立计算。在策略未完成样本外验证前，只展示事实指标，不生成加仓、持有、减仓等操作建议。

## 已确认的现状

- 基金净值、基金分类和用户自定义周期已经进入分析请求。
- `benchmark_profile` 可以按基金代码保存版本化业绩比较基准，并已有基准快照缓存能力。
- 当前 `CSI300_95_CASH_5` 实现只计算了 `95%` 沪深300价格指数日收益，现金腿被当作零收益；因此它不能被标记为完整复现的官方业绩比较基准。
- 当前基金分析仅计算收益、波动和回撤，并以 `CATEGORY_STRATEGY_UNVALIDATED` 停止操作建议，符合本阶段的安全边界。

## 范围

本阶段只支持境内指数基金 `INDEX_FUND`。`QDII_INDEX_FUND`、`OTHER_INDEX_FUND`、商品、主动股票、混合、债券和货币基金保持 `UNAVAILABLE`，后续按各自数据合同独立设计。

首批实现内容：

1. 修正基准数据语义，区分“官方业绩比较基准”“跟踪指数参考”和“不完整近似基准”。
2. 只有基金代码精确匹配的有效基准配置才可进入指数基金相对分析；不得使用基金类型级通用基准代替基金合同约定。
3. 对每个用户周期分别计算基金收益、基准收益、超额收益、跟踪差、年化跟踪误差、相关性和相对净值回撤。
4. 暴露基准来源、配置版本、快照版本、成分、有效期、覆盖率和失败原因。
5. 继续禁止操作建议，直至后续独立的验证报告达到启用标准。

## 基准数据合同

`benchmark_profile.composition_json` 是可执行的数据合同，不再只作为说明文本。每个成分必须声明：

- `seriesType`：`MARKET_INDEX` 或 `ANNUAL_RATE_SERIES`；
- `code`：指数或利率序列代码；
- `weight`：组合权重；
- `returnType`：价格收益、全收益或年利率转换规则；
- `sourceUri`、`sourceVersion` 和有效日期。

组合日收益按各成分当日收益加权后链式累计。任何成分缺失、权重和不为 `1`、收益口径不支持或日期覆盖不足时，整个官方基准返回 `BENCHMARK_INCOMPLETE`，不得把缺失成分按零收益处理。

人民银行公开的历史活期存款基准利率作为版本化源数据保存；算法只消费利率序列，不包含基金代码或具体利率常量。指数行情和利率序列的来源版本共同进入快照指纹。

## 分析数据流

1. Java 根据资产代码、分析截止日和 `INDEX_FUND` 分类解析精确基准配置。
2. 基准准备服务取得覆盖最长用户周期所需日期范围的完整快照。
3. Java 将基金净值、基准记录、基准元数据和三个周期配置一起发送给 Python。
4. Python 按日期交集对齐，但同时计算覆盖率；不能通过静默丢弃大量缺失日期制造“完整”结果。
5. Python 对每个 `targetDays` 使用最近 `targetDays + 1` 个对齐观察值独立计算，不能复用主周期结果。
6. Java 保存包含分类版本、基准配置版本、基准快照版本和周期目标的缓存键，旧口径快照不可回退展示。

## 状态与门禁

指数基金相对分析只有以下状态：

- `READY_DESCRIPTIVE`：数据完整，可以展示基准相对事实指标，`adviceStatus=UNAVAILABLE`；
- `BENCHMARK_UNAVAILABLE`：没有精确官方基准配置或行情获取失败；
- `BENCHMARK_INCOMPLETE`：复合基准任一成分或收益口径不完整；
- `INSUFFICIENT_ALIGNED_HISTORY`：对齐后的观察值不足某个周期的 `targetDays + 1`；
- `DATA_QUALITY_BLOCKED`：基金净值或基准数据未通过质量门禁；
- `CATEGORY_STRATEGY_UNVALIDATED`：数据可分析，但策略尚未通过样本外验证，因此不给操作建议。

不允许用 `WAIT`、`继续持有` 等文字伪装成操作建议。不可用时前端展示明确原因和缺失数据。

## 后续策略启用条件

本阶段不启用交易策略。后续只有版本化策略完成时间顺序样本外验证、与官方基准比较、费用和赎回成本压力测试、过拟合控制，并生成可追溯验证报告后，才能由显式部署状态开启建议。任务成功、模型文件存在或单次回测盈利都不构成启用条件。

## 测试

- Python 单元测试覆盖复合基准计算、缺失现金腿失败、日期对齐、三个周期独立结果和不足历史。
- Java 单元与集成测试覆盖精确基准解析、快照版本、请求字段、缓存失效和失败状态透传。
- 前端测试覆盖相对指标、来源信息、各周期切换以及不可用原因，且验证页面不存在基金交易建议。
- 全量运行 Python、Maven、前端测试和前端构建；提交前运行 `git diff --check`。

## 非目标

- 不恢复当前暂停的量化模型训练或自动交易模块。
- 不为主动基金、债券基金、货币基金或 QDII 复用指数基金算法。
- 不依据基金名称猜测基准，不在代码中写具体基金代码、评分阈值或无来源利率。
