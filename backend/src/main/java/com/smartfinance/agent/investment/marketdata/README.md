# 市场数据规则与存储

行情、资料继续使用现有表和现有采集队列。这里仅提供共用的字段规则与采集事实，不拥有用户资产、任务调度或分析策略。

## 唯一规则定义

`analysis-service/config/data-contracts-v1.json` 定义各产品、资料类型的必需字段和单位。Maven 将同一文件及实际标准化配置打入后端资源；Python 与 Java 生成相同的规则散列。

字段、单位和标准化口径变化会使旧数据失效；超时、界面设置和质量阈值不触发存量重采。新增存储字段必须先追加 Flyway 迁移，不能改写已执行的迁移。应用启动时核对当前规则需要的列。

## 现有调用链

业务需求 → `MarketDataRequirementService` → 当前规则的共享采集事实 → 缺失请求区间进入 `MarketDataSyncService` 原队列 → 现有 Python 来源适配 → 原持久化服务。

日线写入与 `market_data_collection_batch` 的批次记录共用事务。研究资料仍写 `investment_research_record`，保留源端原文、规则、来源以及最初可用时间。不兼容日线在事务内用新版响应替换，失败回滚；旧规则价格不参与新版价格或复权基准推导。

`market_data_requirement.prepared_*` 是可重算的查询缓存，必须绑定当前规则并经实际批次复核，不是数据齐全的依据。已删除产品级 `history_coverage_complete`。

## 结果语义

- `DATA`：来源成功返回记录，记录实际日期及数量，不承诺每天都有记录。
- `EMPTY`：来源成功执行请求，但区间内无记录；有期限，之后可重查。
- `CLOSED`：适用市场的可靠日历确认休市，跳过源端请求；同样有期限。
- 请求失败、解析失败和部分响应：保留原任务错误及重试，不登记成功采集事实。

普通行情与当前质量接口统一输出 `close`；基金不可变快照仍保留 `nav` 与再投资因子用于回放。旧快照维持原身份，不能自动获得新版资格。

## 规则升级

升级表结构 → 同时部署 Java/Python 当前规则 → 现有需求对账使不兼容记录进入原队列 → 成功写入新数据和批次。多个用户复用同一份产品数据与采集事实。只处理有效需求及显式配置的范围，不因升级无条件重拉整个市场。

旧 worker 写入前校验租约与规则代际，不能完成新版任务。没有来源证明时保留旧记录，不能补零或把自然日空缺当成来源应提供的数据。
