# 单机容器部署实施记录

目标：在用户已重装的 OpenCloudOS 9.6 x86_64 服务器上，通过 www.zxxc233.cn 提供服务，形成可重复的更新和备份流程。

已确认：ICP 已备案；Docker 已安装，Compose 正在核验；系统盘 40GB，重装后剩余约 37GB，内存约 3.6GiB。公网只开放入口 TCP 80/443，SSH 沿用用户的来源限制。

沿用现有 Java、Python、Vue、MySQL、Redis 调用链，不改业务逻辑。前端入口容器提供静态文件、API 代理和自动 HTTPS。数据库、上传文件、分析快照/模型和证书分别持久化。

## 实施顺序

- [ ] 编写并运行配置初始化、更新失败、备份失败的行为测试。
- [ ] 添加三个镜像、Compose、入口配置和安全构建上下文。
- [ ] 添加初始化、备份、按版本部署和串行源码构建入口。
- [ ] 添加可选的镜像构建工作流和操作文档。
- [ ] 执行脚本测试、构建及独立审查。

## 约束

不将 application-local.yml、密钥、运行数据、开发依赖送入构建上下文。随机生成数据库密码、JWT 密钥和内部令牌；初始化不能覆盖已有配置。

拉取失败不能停止当前服务。备份失败应重启原服务并中止。新版本失败不能标记成功，也不能自动降级可能已迁移的数据库。

首次源码构建按服务串行执行；后续推荐用预构建的版本镜像。内存限制为保守初始设置，不能当作容量测试结论。

本地没有 Docker 引擎；容器启动、真实 MySQL 迁移、HTTPS 和业务访问必须在服务器验收后才能宣称上线。

用户已确认全新部署并完成重装，本轮直接落实该范围，不重复请求实施许可。改动暂不提交、不推送、不发布镜像、不自动操作服务器。
